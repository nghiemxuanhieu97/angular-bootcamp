# Angular Bootcamp Repository Instructions

## Project purpose

This repository stores a fast-paced Angular learning bootcamp for a Java Backend Developer with six years of experience.

The learner:

- Learns quickly.
- Prefers understanding mechanisms and flows instead of memorization.
- Prefers storytelling and problem-driven explanations.
- Wants comparisons with Java when useful.
- Needs practical Angular knowledge as quickly as possible.
- Does not want excessive documentation or unnecessary files.

## Repository structure

Each lesson must contain only:

- README.md
- Theory.md
- Questions.md
- Answers.md
- Review.md
- Assets/ only when images or diagrams are actually required

Do not add any additional lesson files unless explicitly requested.

## Lesson workflow

Each lesson follows four phases:

1. Theory
2. Clarification
3. Questions and exercises
4. Review and feedback

## File responsibilities

### README.md

Contains only:

- Lesson name
- Problem being solved
- Learning objectives
- Estimated study time
- Prerequisites
- Lesson status
- Previous lesson
- Next lesson

### Theory.md

Contains:

- Story
- Problem
- Pain
- Solution
- Simple mechanism
- Java comparison
- Angular application
- Important points
- Advanced notes that can be postponed

Do not place quiz questions in Theory.md.

### Questions.md

Contains only the knowledge-check questions.

Do not include the learner's answers or mentor feedback.

### Answers.md

Contains the learner's original answers.

Preserve the learner's wording and reasoning.

Only fix obvious Markdown formatting issues. Do not rewrite the answers.

### Review.md

For every question, include:

1. Full question
2. Full original learner answer
3. Score
4. What is correct
5. What needs improvement
6. A more accurate explanation
7. A concise senior-level answer

At the end, include:

- Overall score
- Learner strengths
- Improvement areas
- Knowledge seeds
- Progress summary

## Writing style

- Use Vietnamese.
- Keep explanations clear and practical.
- Use storytelling where useful.
- Explain why a concept exists before explaining syntax.
- Compare with Java when it helps.
- Avoid unnecessary academic detail.
- Mark non-essential deep topics as Advanced Note.
- Prefer short sections over long paragraphs.
- Do not repeat the same explanation across multiple files.

## Safety rules for updates

- Inspect existing files before editing.
- Preserve existing learner answers.
- Do not overwrite completed lessons without explaining the changes.
- Do not create extra files.
- Do not rename lessons without explicit permission.
- Update ROADMAP.md and KNOWLEDGE_GRAPH.md only when lesson status or knowledge coverage changes.
- Show a summary of changed files after completing a task.
